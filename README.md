# MINS_labs — Лабораторные работы

Репозиторий содержит лабораторные и практические работы, выполненные в рамках обучения в магистратуре по направлению, связанному с интеллектуальными системами и сервисами.

## Содержание репозитория

| Работа | Описание | Основные технологии |
|---|---|---|
| **Лабораторная работа № 1** | Разработка REST API для AI-сервиса агроскоринга. Реализация эндпоинтов, валидации входных данных, бизнес-логики, обработки ошибок и документации API. | Python, FastAPI, Pydantic, Uvicorn |
| **Лабораторная работа № 2** | Расширение AI-сервиса агроскоринга: сохранение прогнозов в базе данных, пакетная обработка запросов, управление нагрузкой, обработка тайм-аутов и интеграция с внешней языковой моделью. | Python, FastAPI, SQLite, asyncio, Pydantic, LLM API |

## Лабораторная работа № 1. Agro Scoring API

### Цель работы

Разработать REST API для AI-сервиса оценки рисков сельскохозяйственных предприятий, обеспечивающий приём исходных данных, выполнение прогноза и возврат результатов клиенту.

### Основные задачи

- Реализация HTTP-интерфейса с использованием FastAPI.
- Описание входных и выходных данных с помощью Pydantic-моделей.
- Проверка структурных ограничений и бизнес-правил.
- Реализация логики оценки риска сельскохозяйственных предприятий.
- Обработка HTTP-ошибок и некорректных запросов.
- Формирование документации API с помощью OpenAPI и Swagger UI.
- Разделение приложения на компоненты для упрощения сопровождения и развития.

### Результат

Реализован REST API, позволяющий передавать данные сельскохозяйственного предприятия и получать оценку риска. Предусмотрены валидация входных данных, обработка ошибок и автоматическая документация эндпоинтов.

## Лабораторная работа № 2. Расширение Agro Scoring API

### Цель работы

Расширить функциональность AI-сервиса, обеспечив сохранение результатов, эффективную обработку параллельных запросов и взаимодействие с внешним LLM-провайдером.

### Основные задачи

- Сохранение результатов прогнозирования в SQLite.
- Использование `request_id` для идентификации запросов и поиска сохранённых результатов.
- Реализация пакетного прогнозирования (**batch processing**).
- Организация очереди инференса и динамического объединения запросов в пакеты (**batching**).
- Реализация механизма ограничения нагрузки (**backpressure**) при переполнении очереди.
- Ограничение времени выполнения операций и обработка тайм-аутов.
- Добавление фильтрации и постраничного вывода результатов.
- Интеграция с внешним LLM-провайдером для обработки текстовых запросов и формирования дополнительных ответов.
- Обработка ошибок базы данных, модели и внешнего сервиса.

### Результат

Расширен AI-сервис агроскоринга: реализованы хранение истории прогнозов, пакетная обработка, ограничение нагрузки, контроль времени выполнения и интеграция с внешней языковой моделью. Сервис предусматривает обработку ошибок и предоставляет единый REST API для взаимодействия с клиентскими приложениями.

## Технологический стек

- **Python** — основной язык разработки.
- **FastAPI** — реализация REST API.
- **Pydantic** — описание схем и валидация данных.
- **Uvicorn** — запуск ASGI-приложения.
- **SQLite** — хранение результатов прогнозирования.
- **asyncio** — асинхронная обработка запросов и организация очереди.
- **LLM API** — взаимодействие с внешней языковой моделью.
- **OpenAPI / Swagger UI** — описание и интерактивное тестирование API.
- **pytest** — автоматизированное тестирование.

## Запуск проекта

Для запуска конкретной лабораторной работы перейдите в соответствующий каталог. Например, для второй работы:

```powershell
cd lab2
```

Создайте виртуальное окружение:

```powershell
python -m venv .venv
```

Активируйте его в Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Установите зависимости:

```powershell
pip install -r requirements.txt
```

Запустите API:

```powershell
python -m uvicorn agro_api.main:app --reload
```

После запуска документация Swagger UI будет доступна по адресу:

`http://127.0.0.1:8000/docs`

Проверить состояние сервиса можно через эндпоинт `/health`, если он предусмотрен в соответствующей версии проекта.

## Тестирование

Если в каталоге лабораторной работы предусмотрены автоматизированные тесты, их можно запустить командой:

```powershell
python -m pytest
```

Для ручной проверки API можно использовать Swagger UI, отправляя запросы к эндпоинтам и проверяя коды HTTP-ответов, структуру возвращаемых данных и обработку ошибок.

## Назначение проекта

Работы направлены на изучение принципов разработки интеллектуальных сетевых сервисов: проектирования REST API, организации инференса, валидации данных, хранения результатов, управления нагрузкой и интеграции моделей машинного обучения с внешними сервисами.

Репозиторий используется для хранения исходного кода, тестов, документации и результатов выполнения лабораторных работ.
